### Anti-drift statement (charter §7)

1. **Goal alignment.** The decisions collected here govern active daily opportunity discovery, net-of-cost evaluation and the compounding of realized net profit with losses reducing size (`CH:L8`). Daily discovery is not daily execution; no row creates a trade quota, a fixed holding period or a BTC-only scope (`CH:L10`).
2. **Branch, SHA, runtime identity.** `main` = `46578aa`. Runtime behaviour is SOURCE_VERIFIED at the documented-deployed commits only; runtime values are RUNTIME_VERIFIED for 2026-10-31 only (BL-11). This file makes no runtime claim.
3. **Scope.** WP1 consolidation for the WP3 gate (`CH:L50`, `CH:L52`); all of R1–R9 through their owner gates. Exclusions: no new finding about code, no generic re-audit (`CH:L16`), no protected data.
4. **Evidence class.** Options and trade-offs are DOCUMENTED_ONLY: they are what the cited source states, not verified effects. ERG-01 statements keep the class ERG-01 gives them (mostly INFERRED). Other claims carry their class inline.
5. **Permission class.** Read-only documentation. Each DG row names the permission class of the action it would unlock, in the charter vocabulary read-only / safe dev / strategy-version change / protected experiment / deployment; none implies another (`CH:L65`).
6. **Deliverables and acceptance.** The decision table with its completeness cross-index (section 1), the WP3 gate map (section 2), the log entry (section 3) and the anti-drift check (section 4). Acceptance: a clean self-check and owner review. Owner gate: none for writing; every DG row is itself a gate. Rollback: discard the uncommitted file.
7. **DEVIATION ALERT.** None raised; see [section 4](#4-anti-drift-check).

## 1. Consolidated owner-decision table

**How to read.**
- One DG row per distinct decision. Where several source IDs ask the same question, they are merged into one row and all of them are listed; [section 1.7](#17-completeness-cross-index) maps every source ID to its row.
- **Options and trade-offs** are copied from the cited source, in its order, which is not a ranking. Where a source poses a question without options or trade-offs, the row says so; nothing is invented.
- **Needed by** names the pack documents whose design waits on the decision. **Blocks** names the R sub-items and the OF-T, SE and PR-C changes that cannot be activated, or in some cases built, until the decision is recorded, followed by the workplan tasks (WP-A01 to WP-F07) and gated items (WP-G01 to WP-G34) that name the same gate (WPL §4, §6, §7.1).
- **Interface names** follow the workplan's canonical choices WP-IR-01 to WP-IR-09 (WPL §8): `RejectionRecord` with `stage` F0 to F7, `sub_stage` and `detail`; `risk_plan` on `Candidate`; one capacity authority at F7; codes such as `F6.rank_below_cap` and `F7.capacity_full`; the cost-model identifiers `legacy_tracker_v1`, `research_baseline_v1` and `research_stress_v1`.
- **Unlocks** is the permission class of the action that the decision would allow next (`CH:L65`). A decision is never itself that action: each still needs its own approval, test evidence and, for Paper changes, a declared version boundary (`CH:L51`; DFP:L63).
- **Until a row is decided, current values and behaviour stay in force and nothing new is activated** (OFN:L492; PRC:L506). A decision is recorded with its date, approver and chosen option in the charter §7 log (`CH:L69`; section 3). A decision that changes an A29 parameter, the goal or the risk policy is a formal governance change (`CH:L52`, `CH:L69`).

## 4. Anti-drift check

**Basis.** Charter §7 item 7 requires a DEVIATION ALERT before work that changes the objective, treats a different strategy's result as transferable, adds unregistered tuning, forces trades, mandates BTC-only, treats unrealized gains as cash or bypasses A29 (`CH:L67`); the non-goals are daily trade quotas, fixed 14-day holds, mandatory BTC-only scope, SMA200 as sole production strategy, automatic deployment and changing a strategy to improve historical metrics without pre-registration (`CH:L10`); and the charter forbids a repeated generic audit (`CH:L16`). The nine checks below cover those items.

**Method.** All eight pack files were read in full, every line, on 2026-11-01: the five design documents for table 4.1, the workplan and the README for table 4.2, and this file again after each change. Then case-insensitive `grep -n -i` scans ran over all eight files for these terms: quota; per day; daily trade; forc (force, forced); minimum trade; minimum frequency; BTC-only; BTC only; BTC/USDT only; SMA200; 14-day; 14 day; minimum holding; holding period; holding ceiling; fixed dur; free cash; unrealized gain; unrealized; unrealised; tune and tuning; optimi; calibrat; HIS-05; transfer; attribut; bypass; without approval; without owner; without a PR; re-audit; generic audit; repeat; pause; D (stop); daily discovery; discovery; PF_net; 1.15; DSR; cluster t. Every hit was read in context.
