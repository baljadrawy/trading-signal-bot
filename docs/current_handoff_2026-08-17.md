كون الخدمات `healthy` على أنه سماح بالتداول؛ حالة السماح موثقة أدناه.

- الفرع: `integration/research-pipeline`.

  `risk:loss_streak_halt`.

  للسياسة أو تطبيق لـ `learned_gates` أثناء النافذة الثابتة.
- لا يُصفر سجل التعلم أو الصفقات؛ التاريخ السابق محفوظ للتدقيق.

## لماذا توقف البوت؟

- ظهرت 9 خسائر صافية متتالية بلغ مجموعها -11.818 نقطة مئوية على وحدات الصفقات.
- 8/9 كانت momentum، وآخر سبع صفقات من `sb-2026.08` كانت momentum في نافذة
  risk-on واحدة؛ التنويع الرمزي أخفى تعرضاً استراتيجياً/سوقياً مترابطاً.
- أربع ضربات وقف سببت نحو 83% من الخسارة.
- خمس صفقات وصلت T1 ثم خرجت بما كان يسمى break-even، لكنه كان -0.40% صافيًا
  بسبب 0.10% stop slippage و0.30% round-trip cost.
- لا دليل على overshoot أو خلل حساب المؤشرات؛ الخلل الأساسي كان أن وضع التعلم
  الحي يختار أول setup صالح بلا ترتيب جودة أو حد تركّز للنوع/النظام.

بعد الإصلاح، أغلقت ALLOUSDT عند T3 بربح +4.14% وأغلقت ZECUSDT عند وقف التعادل
الصافي بربح إجمالي +0.30%. أصبح عداد الخسائر المتتالية صفراً، لكن القاطع بقي
مقفلاً عمداً حتى تنتهي مراجعة الصفقات القديمة؛ لا استئناف تلقائي.

## ما تم تنفيذه

- توحيد OHLCV والشموع المغلقة وUTC وwarm-up عند 200 شمعة.
- اختبارات مستقلة للمؤشرات ووحداتها وتعريفاتها.
- توحيد الخروج الحي والباكتيست، وأولوية الوقف، والانزلاق وtime-stop.
- إعادة bracket من سعر التعبئة الفعلي.
- walk-forward مع purge/embargo، وتحليل محفظة بعد التكلفة.
- حارس مخاطر يحسب المحقق وغير المحقق ويحد التعرض والخسارة والتراجع.
- تحديث المخاطر فور كل إغلاق، لا عند محاولة الدخول التالية فقط.
- سقف الرمز 10%، النوع 40%، النظام 50%، والتعرض الإجمالي 80%.
- Canary الجديدة محدودة بمركز واحد بقيمة 50 USDT.
- اختيار ثابت: أضيق spread، ثم أعلى سيولة، ثم symbol/timeframe لكسر التعادل.
- تسجيل المرشحين المختارين والمرفوضين وسبب القرار وspread والسيولة في evidence.
- وقف T1 أصبح يحمي تعادلاً صافياً قدر الإمكان، ومقيداً بسعر T1.

## أوامر فحص آمنة عند العودة

```bash
docker compose ps -a
docker exec postgres psql -X -U trading_signal_bot -d trading_signals -Atc \
  "SELECT date,is_trading_paused,pause_reason,daily_pnl_percent,consecutive_losses FROM risk_management WHERE date=CURRENT_DATE;"
docker exec postgres psql -X -U trading_signal_bot -d trading_signals -P pager=off -c \
  "SELECT symbol,timeframe,opened_at,highest_target_hit,status FROM active_trades WHERE status='open' ORDER BY opened_at;"
docker compose logs --tail=100 scanner signal_engine trade_tracker
```

لا ترفع القاطع لمجرد أن `consecutive_losses=0`؛ الصفر نتج عن صفقة رابحة لاحقة،
بينما القاطع الثابت يحتاج قرار استئناف واعياً بعد إغلاق الإرث القديم.
