# قاطع سلسلة الخسائر — دليل التشغيل والاستئناف

يوثّق هذا الملف عقد الاسترداد الوحيد المعتمد لقاطع `loss_streak_halt`.
لا تستخدم أي إجراء آخر لرفع القاطع.

## ما الذي يُفعّل القاطع

`evaluate_new_trade()` يرفض أي دخول جديد عندما تبلغ الخسائر الصافية المتتالية
`STOP_ON_CONSECUTIVE_LOSSES` (حالياً 7). العدّ:

- يُعاد بناؤه من `trade_results` عند كل تقييم (لا قيمة مخزَّنة).
- صافي بعد الرسوم: صفقة رابحة إجمالاً وخاسرة بعد الرسوم تُحتسب **خسارة**.
- يُصفَّر بأول إغلاق `net >= 0` من نهاية السجل (التعادل الصافي يُصفِّر).

**القاطع fail-closed:** يمنع الدخول الجديد فقط؛ إدارة الصفقات المفتوحة
والأهداف والوقف تستمر كالمعتاد.

## ما الذي **لا** يرفع القاطع

| الإجراء | الأثر على القاطع |
|---|---|
| `/resume` | **لا يرفعه.** يرفع الإيقاف الإداري فقط |
| إعادة تشغيل العملية/الحاوية/الخادم | **لا يرفعه** — الحالة تُعاد من القاعدة |
| إعادة النشر | **لا يرفعه** |
| تغيّر اليوم أو الأسبوع | **لا يرفعه** — العدّاد ليس له بُعد زمني |
| تعديل `risk_management.consecutive_losses` يدوياً | **بلا أثر إطلاقاً** — هذا العمود عرض/تليمتري ولا يُقرأ في قرار القبول |
| حذف أو تعديل `trade_results` | **ممنوع** — ولا يوجد مسار كود يفعله |

## كيف يُرفع القاطع

### الحالة أ — توجد صفقة مفتوحة (استرداد ذاتي)

إذا كانت هناك صفقة مفتوحة عند بلوغ القاطع، فقد تُغلق لاحقاً بربح فتُصفِّر
السلسلة ويُرفع القاطع **تلقائياً** بلا أي تدخل. هذا ما حدث فعلياً في حادثة
2026-08-17 (خمس صفقات مفتوحة، أُغلقت اثنتان بربح).

`/status` يعرض في هذه الحالة عدد الصفقات المفتوحة التي قد تكسر السلسلة.

### الحالة ب — لا توجد صفقة مفتوحة (يحتاج إقراراً صريحاً)

بلا صفقة مفتوحة لا يمكن للسلسلة أن تتحرك ذاتياً: القبول مرفوض، فلا إغلاق
جديد، فلا فوز يُصفِّر. **هذه الحالة تحتاج إقراراً يدوياً.**

الخطوات:

1. **حقّق أولاً.** راجع سبب السلسلة (تركّز نوع/نظام؟ خلل تنفيذي؟ ضربات وقف؟).
   لا ترفع القاطع لمجرد رغبتك في استئناف التداول.
2. تأكد أنه **لا توجد صفقات مفتوحة**:
   ```bash
   docker exec postgres psql -X -U trading_signal_bot -d trading_signals -Atc \
     "SELECT COUNT(*) FROM active_trades WHERE status='open';"
   ```
3. نفّذ الإقرار من تلجرام (من حساب المالك حصراً):
   ```
   /recover_risk <سبب صريح>
   ```
   مثال: `/recover_risk راجعت الصفقات التسع، لا خلل تنفيذي، السبب تركّز momentum`

   السبب **إلزامي** — الأمر يُرفض بدونه.
4. إذا كان التداول موقوفاً إدارياً أيضاً، نفّذ `/resume` بعدها.
   **الترتيب: `/recover_risk` يرفع قاطع المخاطر، و`/resume` يرفع الإيقاف
   الإداري. كلٌّ منهما منفصل عن الآخر عمداً.**

## ماذا يفعل الإقرار بالضبط

يُسجَّل صفّ في `risk_recovery_events` يحمل **حدود حقبة جديدة**
(`epoch_started_at`). بعده يبدأ حساب السلسلة من هذه الحدود فقط.

**الطابع الزمني للحقبة تولّده قاعدة البيانات** (`NOW()`) داخل نفس المعاملة، تماماً
مثل `trade_results.exit_time` — فالمصدر الزمني واحد ولا يوجد انحراف ساعة بينهما.

**التسلسل مع فتح الصفقات:** مسار الإقرار ومسار فتح المركز يأخذان **نفس القفل
الاستشاري** (`pg_advisory_xact_lock`) على مستوى المعاملة. لذلك لا يمكن أن يُقَرّ
استرداد بناءً على «دفتر خالٍ» بينما صفقة تُفتح في نفس اللحظة: إما أن الصفقة
اكتملت قبل القراءة فيراها الإقرار ويُرفض، أو أنها محجوبة حتى ينتهي الإقرار.
القفل يتحرر تلقائياً عند COMMIT أو ROLLBACK أو انهيار العملية.

> **ملاحظة دقيقة:** قيد `CHECK (open_positions_at_recovery = 0)` في المخطط يضمن
> **سلامة القيمة المسجَّلة** فقط — لا يثبت وحده أن المحفظة كانت خالية فعلاً.
> الضمان الحقيقي يأتي من القفل المشترك + إعادة القراءة داخل المعاملة.

- **لا يُحذف ولا يُعدَّل أي سجل في `trade_results`.**
- الحادثة تبقى قابلة للتدقيق بالكامل.
- الحماية **لا تُعطَّل**: سبع خسائر جديدة بعد الإقرار تُفعّل القاطع مجدداً.

## التحقق من نجاح الاستئناف

```bash
# الحقبة المسجَّلة ومن أقرّها ولماذا
docker exec postgres psql -X -U trading_signal_bot -d trading_signals -P pager=off -c \
  "SELECT id,epoch_started_at,acknowledged_at,acknowledged_by,reason,
          consecutive_losses_before
   FROM risk_recovery_events ORDER BY id DESC LIMIT 5;"
```

ثم `/status` في تلجرام — يجب أن تختفي أسطر القاطع وتعود الحالة
`✅ يبحث ويراقب`.

## سجل التدقيق

كل إقرار يجيب على: **من** (`acknowledged_by`)، **متى** (`acknowledged_at`)،
**لماذا** (`reason`)، **أي قاطع** (`halt_reason`)، **السلسلة قبله**
(`consecutive_losses_before`)، **وحالة الدفتر المسجَّلة**
(`open_positions_at_recovery`).

## حالات العرض في `/status`

| الحالة | المعنى |
|---|---|
| `✅ يبحث ويراقب` | تشغيل طبيعي |
| `⏸️ موقوف` | إيقاف إداري (`/resume` يرفعه) |
| `🛑 قاطع سلسلة الخسائر` | القاطع نشط وصفقة مفتوحة قد تكسره تلقائياً |
| `🛑 … (يحتاج إقراراً يدوياً)` | القاطع نشط بلا صفقات مفتوحة — يحتاج `/recover_risk` |

**مهم:** الماسح قد يعمل ويولّد إشارات بينما القاطع نشط. `/status` يصرّح بهذا
حتى لا يبدو النظام سليماً وهو عاجز عن الدخول.
